# 0.28.0 上传页重连状态与会话刷新

日期：2026-09-14（Australia/Adelaide）。基线为容量切片
`df9955e366544354d550fa6594759f6cc63fe1ad`；本次只改变上传页面脚本和相关文档。
修订页面 Git blob：`def8ee968ebbf7be712794a6fe5891c77d568b71`。

## 可复现问题

[容量验收](iteration-0.28.0-upload-storage-threshold.md)的普通 Stop/Start 中，上传页已经
收到新的容量数据，但全局横幅仍为 `状态刷新失败：Failed to fetch`。
成功的 `refresh()` 没有关闭由 `poll()` 写入的错误；CSRF 也只在首次页面连接时读取。
因此长时间保留的页面既可能显示过期错误，也可能继续使用前一个服务实例的会话值。

ignored Node 探针先在原页面复现：断开后 danger；连接恢复后仍 danger，模拟新服务的
会话值未采用。失败/恢复前后输入与焦点均在，自动 POST 为 0；不是表单丢失或远端结果重试问题。

## 修正

- 每次上传 `refresh()` 先通过原有只读 session 接口取得当前实例的 CSRF，再读取状态。
  初次连接共用同一入口，不重复读取 session。
- 全局反馈记录其来源。成功刷新只替换由轮询/初次连接写入的错误；用户操作反馈保持原样。
  连接恢复不宣称全部数据读取成功，局部读取失败仍显示在原记录区和封面区。
- 没有重发 POST、自动登录、确认、上传或 retry。仍使用原同源、CSRF、显式确认与 receipt 合同。
  输入、选区、账号/任务节点、二维码及轮询调度的所有权未改变。
- 容量警告将“导入视频”改为“媒体写入”，覆盖相同门槛下的视频与封面。

## 验证

同一个 ignored Node 探针对修订后页面通过以下断言：
断开 danger → 恢复 muted、采用当前 session、输入/焦点保留、业务错误不被刷新清除、
局部读取警告仍显示，自动 POST 为 0。没有修改既有 harness 或 tracked tests。

`pytest -q tests/test_upload_ui.py tests/test_ui_design_system.py tests/test_upload_api.py`：
**118 passed in 28.66s**。

真实浏览器使用新的空 app root、端口 18878；普通 Start 的阈值为 512 MiB：

1. 输入“重连后保留输入”，焦点位于标题，选区 `[6,7]`。
2. Ctrl+C 正常停止；页面实际显示 `状态刷新失败：Failed to fetch` / danger。
3. 相同根与端口重新普通 Start；无需重载浏览器，页面显示
   `上传器已重新连接；请核对各区状态。` / muted，标题、焦点和选区保持。
4. 点击“刷新状态”后显示 `状态已刷新。`，后续 **86.332 秒**轮询仍保持该操作反馈和标题。
5. 两次应用运行均记录 `local_app.stopped / reason=normal`；所有自有进程退出、端口释放。
   batch 的 Ctrl+C/Y 外层退出码为 1，未将其冒记为 0。

浏览器中的断开错误来自本次主动正常停机；这不是零错误网络场景。
旧会话更换与零自动 POST 由离线协议探针明确验证；实际浏览器未进行登录或平台动作。
日志、JSON、截图观察和探针留在 ignored 本地验收区。

此结果关闭上述重连缺陷，不覆盖真实账号会话、上传执行中的远端恢复或持续生产负载。
