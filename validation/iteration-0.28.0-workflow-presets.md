# Iteration 0.28.0 workflow preset evidence

Date: 2026-09-09

This record supersedes the earlier narrow preset validation. The initial store did not validate nested upload fields or verify its stored digest, and only bound transcription/translation authorization. The initial UI did not restore AI toggles, language, voice, copyright, schedules or all platform overrides. Those gaps are now corrected in the current source milestone.

`WorkflowPresetStore` remains a bounded atomic JSON file for one control-plane process, with no new dependency, database or daemon. Save validates existing workflow and upload metadata contracts, including nested override keys/types. Read verifies record/profile digests, shape, timestamps, unique IDs and size/count limits. Same normalized name and profile return the existing record, so a lost save response does not duplicate it. The store excludes the source URL field, credentials, account session bindings, full AI authorization objects and execution egress consent. Arbitrary user-authored title/description text is still content, not a credential-detection system.

New AI presets store `synthesis_authorization_sha256` alongside the transcription/translation digests. Materialization binds current full authorization and retains current download credential/confirmation/egress choices. Valid drift in any of the three operation definitions is blocked; malformed binding is rejected. Legacy AI presets without the synthesis digest remain readable but cannot materialize. Non-AI presets remain usable. Local saving does not require cloud consent and never creates a workflow; execution still requires current consent and upload preflight binds current account sessions.

The production workflow page restores segment labels/times, independent cover text/time/ratio, source/target/dubbing languages, model/voice, original-audio handling, copyright, scheduling, automatic-execution intent and per-account metadata. Per-account overrides remain visible in a details panel and survive detaching a preset; changing a common field replaces its corresponding override. Missing accounts or models cannot silently fall back, refresh preserves explicit missing model/voice selections, and cloud consent resets on apply. Preset selection waits for initial account/capability loads; saving does not overwrite edits made while its request is pending. These controls reuse the existing design-system CSS; no liquid-glass production redesign is claimed.

Current local checks, all PASS:

- `validation/local/validate_workflow_presets.py` and `validate_workflow_preset_boundaries.py`: three authorization digests, current consent, local save, strict nested fields, legacy behavior, duplicate save, corruption and storage bounds.
- `validation/local/validate_workflow_preset_api.py`: actual FastAPI/ASGI routes, CSRF, save/list/get, current-consent rejection, fresh synthetic account binding, workflow idempotency, malformed metadata and corrupted-file error responses.
- `validation/local/validate_workflow_preset_browser.cjs`: real installed Chrome rendering the production HTML/CSS with synthetic API responses. Verified transmitted payload for AI/cover/voice, three-platform independent titles/schedules and video-channel draft mode, detach preservation, missing capability/voice after refresh, save-without-consent, edits during pending save, initial load race and 320px horizontal-overflow boundary. Desktop screenshot is ignored `validation/local/preset-browser-desktop.png`.
- [Real-domain offline chain](iteration-0.28.0-full-chain-smoke.md): preset save/reload/materialize with new synthetic login sessions, actual isolated AI operation entries and FFmpeg audio output, three synthetic platform acknowledgements.

All temporary scripts/results remain ignored and are not committed. This is current-source engineering evidence only; real model quality, internet extraction, platform authentication, actual upload/publication and a new frozen release receipt remain unverified.
