## 资源与兼容性

- 原件下载采用 1 MiB 内存阈值和 64 KiB 块；大文件滚入 OS 临时文件。全量返回 N 字节需源读 N、临时写 N、临时读 N；Range 同样先校验完整 N，再读区间 R。首字节等待完整校验，并发临时磁盘需求约为各原件大小之和；空间不足安全返回 409 并关闭临时文件，没有预留容量机制。HEAD 保留原 GET-only 路由的 405 行为。
- 旧上传 runtime Schema 1 会明确要求重建。停止应用后只将旧 runtime 子目录改名留档，再向原上传 root 安装；数据库、媒体和账号文件保留。具体见 [运行时升级](../docs/UPLOAD_RUNTIME.md#从旧运行时升级)。本轮未移动或重建用户现有运行时。
- 运行时 manifest 是可由本机用户修改的完整性记录，不是数字签名。浏览器和外部 CPython 基线检测安装后漂移，不证明其发行签名，也不抵御同权限用户同时重写整个应用和校验依据。
- 本次心跳表示 supervisor 最近观测到自己拥有的 Worker 进程存活，不证明任务推进、平台整体可用或隔离执行。工具接口的静态 network_download_enabled=false 与实际运行接口的字段分别解释。
- 上传完整备份/恢复、长期压力与资源上限、Linux 环境验收以及真实平台矩阵仍是后续工作；F-07 的结构校验修复不等于完成 T07 的备份工具。Apple 风格整站迁移保留在最后 T16，本轮只调整修复所需控件。

## 验证结果

- 全套复验：**1941 passed、8 skipped，212.15 秒**；8 项跳过来自 Windows 上不可执行的 POSIX/root/getfacl/Unix socket 条件。首轮 2 个失败是旧提示及旧版本正则断言未同步，更新后重新跑完全部测试；没有删除测试或缩小门槛。
- 开发依赖：`uv sync --extra dev --locked --offline` 与 `uv pip check` 通过，23 个已安装依赖兼容。发行清单覆盖 306 个文件、198 个 Python 文件；AST、当前版本/锁合同、本地链接及 diff whitespace 检查通过。
- 普通 Start：独立空 app root，实际页面显示本机 Worker 运行中；Ctrl+C 后三个自有进程全部退出、18847 端口释放，日志停止原因为 normal，页面转为未知。PTY 的 shell 中断状态为 1，不拿它作为应用异常退出证据；生命周期以自有进程、日志和端口共同核对。
- 实际浏览器：独立 18848 合成后端实例，完成下载成品导入、本地草稿、刷新/轮询保持空来源与折叠状态、取消。加入 201 条明确的合成终态历史后，首屏 200 条、“加载更早任务”后 202 条；分页控件 44px，页面无横向溢出。账号操作记录为 0，HTTP 登录/检查/最终确认 POST 为 0；合成 submitted 行仅由测试夹具写入，不是投稿证据。停止后端口释放。
- 容量：0/1/200/201/1000 条下所有来源和任务均可无重复翻页取回，最旧 running 优先且可请求取消。1000 条/5 页读取：来源 1.854 秒、任务 0.038 秒。此为单机小型合成基准，不是长期容量承诺。
- 原件快照：16.5 MiB 合成字节、1 MiB 阈值滚盘，快照核验 0.031 秒，读取已验证快照 0.005 秒；磁盘缓存与并行负载影响这些数值，不外推到大视频或网络盘。
- 运行时实装：在新建独立 root 安装成功，显式 `--check`（CLI 与本地 Chromium 页面）通过；2771 个 runtime 文件/984153133 字节，加 2766 个外部 CPython 文件。冷检查 8.454 秒、10 秒 TTL 内缓存 0.001 秒、到期元数据复核 2.552 秒、执行前无缓存全检 8.282 秒。无账号执行准备在全检后返回 account_missing，操作目录数量为 0。实际运行时解释器也验证相邻恶意 pyc 对照为 evil、生产隔离命令为 safe。
- 旧运行时只读检查：返回 runtime_upgrade_required，旧 manifest hash 前后相同；用户账号、媒体和原 runtime 未移动或重建。
- 精确源码 ZIP 和 wheel 的独立安装证据在**制品旁外置**的 `verification/source-install-report.json`、`verification/wheel-install-report.json`；绑定归档 hash 和本节完整应用身份，避免把安装后才产生的报告循环嵌入被验证 ZIP。本地源码 Setup、重复 Setup、Start check 与 wheel 的 13 个命令入口由仓库验证脚本检查，结果以对应报告的 status 与步骤为准。
