## 修复与集成验证

修复草稿详情手动折叠后被自动刷新重新展开：按任务 ID 保留实际展开状态，新草稿默认展开，取消、终态、列表重排和新建重试任务彼此独立。新增回归同时检查账号选择、视频选择与二维码状态不被改动。

对下载成品接入上传的验证使用真实下载登记、资产存储和 API 解析，不以替换成品查询函数代替完整关联。联网下载执行器与平台上传执行器均为离线替身；本轮没有请求第三方媒体下载或上传。

新增完整登记链路集成测试 **10 项**：原批次及 duplicate 批次成品入口、真实 owner/asset/artifact 关联、独立副本、原件与下载数据库不变；非 ready 登记、登记 hash 冲突、文件缺失、大小及同大小内容变化均拒绝导入。与既有上传 API/下载成品 UI 的组合回归 **41 项通过**。详情状态修复后的上传前端组 **12 项通过**。

完整回归 **1859 passed, 8 skipped in 202.89s**。8 项跳过均为 Windows 不具备的指定 POSIX 能力。

在独立端口 18842，实际浏览器从最近下载批次打开 ready 成品，点击“用于上传”并显式导入；使用之前已验证的 5 秒、56,111 字节视频，SHA-256 与原登记一致。真实 UI 创建 Bilibili/抖音投稿模式和视频号平台草稿模式共3份本地草稿，验证标题、简介、标签、分区、类型和模式，再逐项取消并返回下载列表，原 ready 成品仍可访问。Bilibili 详情手动折叠后跨自动轮询及手动刷新保持，其他任务展开状态和3个账号选择独立保留；无水平溢出，浏览器 warning/error 记录为空。
