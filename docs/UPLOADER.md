# Bilibili、抖音与视频号上传

Open-Flame 的上传页面位于 `/uploads`，下载首页也有入口。首批平台为 **Bilibili、抖音、视频号**；小红书等平台保留为后续工作。本模块提交本地视频，不会将下载完成自动解释为上传或发布授权。

## 首次准备

1. 先按现有 Windows Setup / Start 流程启动 Open-Flame。
2. 按 [上传运行环境](UPLOAD_RUNTIME.md) 安装独立运行环境，再在上传页刷新状态。运行环境未安装时，下载功能仍可用。
3. 在上传页选择平台，点击“添加并扫码登录”。账号备注可留空自动命名；二维码直接显示在本页。Bilibili、抖音使用各自 App 扫码，视频号使用微信扫码；Bilibili 授权页可能显示 TV 客户端。现有账号可点击“扫码登录”或“重新扫码登录”。
4. 扫码后按手机提示确认，页面自动更新登录状态；成功后可直接选择账号。二维码过期时点击“重新获取二维码”，不需要重新添加账号；取消会关闭本次登录会话。平台要求额外验证时会明确提示，工具不会代替用户完成验证码。

二维码显示成功仅证明取码链路可用；真实扫码、账号权限和后续投稿仍需逐平台验证。二维码只在当前执行上传任务的应用中显示，另一应用实例会明确要求回到该实例。

安装成功和账号检查通过仅说明对应本地步骤可运行，不代表该平台已完成真实投稿验收。

## 从视频到投稿

1. 选择一个本地视频，导入 Open-Flame。支持 MP4、MOV、M4V、WebM、MKV、AVI，单文件上限 2 GiB；实际编码、时长、尺寸还受平台限制。也可以从下载成品的“用于上传”入口导入，经大小与 SHA-256 复核后复制原件。
2. 勾选目标账号，填写标题、简介和标签。首批每次最多选择 20 个账号；同一视频可以创建多个平台的独立任务。Bilibili 必须填写真实分区 ID 和标签，并明确原创或转载；转载必须填写来源。
3. 视频号可选择保存平台草稿或立即发布；Bilibili、抖音目前提供投稿模式。
4. 先创建本地草稿，核对账号、平台、内容和发布模式，再逐项点击确认按钮。创建本地草稿本身不会登录平台、传输视频或投稿。
5. 从任务列表观察结果。后台串行执行上传与账号操作，避免同一登录态并发使用。可以取消排队项，或请求停止正在执行的操作。

首批不包含跨视频批量导入、定时发布、多 P、合集、封面编辑、媒体剪辑或自动生成文案；上述能力不应被当成当前已完成项目。

## 状态含义

| 状态 | 含义与下一步 |
|---|---|
| `draft` | 本地草稿，尚未允许上传；检查后明确确认 |
| `queued` | 已确认，等待执行 |
| `running` | 正在与平台交互；不能据此判断是否已发布 |
| `submitted` | 上游工具报告提交完成；不等于审核通过、公开可见或我们验证了远端作品 |
| `draft_saved` | 上游工具报告视频号草稿已保存；不是公开发布 |
| `failed` | 明确的准备或执行失败；修复原因后创建新草稿 |
| `canceled` | 本地取消；执行已经开始后的不确定结果按 `unknown` 处理 |
| `unknown` | 可能已在平台产生结果；先检查创作者后台，确认不会重复后再显式创建重试草稿 |

重试创建新的本地草稿，保留原任务和关联关系；仍需再次确认。服务重启时，原 `running` 变为 `unknown`，原 `queued` 退回需确认的本地草稿，避免在重启后意外补发。平台审核和作品最终状态目前需在创作者后台核对。

## 本地数据与备份

上传目录在下载数据目录的同级，名称为下载目录名加 `-uploads`。普通 Windows Start 的默认位置是 `%LOCALAPPDATA%\Open-Flame\video-download-control\data-uploads`；开发控制面默认使用源码目录旁的 `data-uploads`。自定义 `--app-root` 会相应改变位置。

上传目录包含 `uploads.sqlite3`、受管媒体 `media`、导入临时目录 `incoming`、账号等私有状态 `private` 和独立工具环境 `runtime`。上传库独立使用 Schema 1，不修改下载 Schema 11，也不复用下载 CredentialProfile 或 Cookie 文件。

**现有下载备份不包含上传目录。** 上传服务没有单独的在线一致备份命令；需要保留上传记录时，先正常停止 Open-Flame，再在本机安全位置备份该上传目录。账号状态及日志、数据库、媒体、运行环境不得加入 Git 或公开交接包。

## 外部测试

需要验证的平台为 **Bilibili、抖音、视频号**。具体用例、真实投稿确认步骤与结果回报模板见 [上传测试计划](UPLOADER_TEST_PLAN.md)。优先先测本地草稿与取消，再由测试员确认是否执行真实上传；视频号“保存平台草稿”同样会传输视频。
