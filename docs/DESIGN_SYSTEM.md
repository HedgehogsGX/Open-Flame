# Open-Flame 界面设计规范

版本：1.3，2026-09-07。适用范围：下载首页、编辑工作台、上传工作台及后续新增的用户界面。用户确定的方向是参考 Apple 的设计风格，提升排版、字体与细节品质，加入适量动态效果，并由后续开发持续沿用。

**状态：T16 生产迁移与本地 G6 验收完成，T18 编辑页接入共享设计系统。** 下载、编辑和上传页现使用同一共享样式、主题脚本、固定静态资源入口与 CSP；[交互式设计预览](design-preview.html)直接读取生产 CSS。T16 的下载/上传页真实 Chromium 矩阵保持历史证据；T18 编辑页另以默认窄视口和 1440×900 验证真实分段、封面与显式导入上传流程。精确 commit、制品 hash 与独立安装结果由包外 release receipt 绑定。本地 synthetic 验收不证明 AI 模型、真实登录、下载、上传或平台审核结果。

## 1. 视觉方向

以精致、安静的桌面工作台为目标：浅灰画布、白色内容面板、墨色文字和蓝色主操作；留白承担分组，字重承担层级，浅边框承担边界，阴影仅承担浮层深度。保留 Open-Flame 的产品名称与识别，不把工具页面改为大幅营销封面。

Apple 的系统字体、随字号组织的字距和行高适合作为排版参考；本项目采用跨平台系统字体回退，并自行确定下方数值。[Apple：The details of UI typography](https://developer.apple.com/videos/play/wwdc2020/10175/)

动效参考即时反馈、空间关系与可中断的交互原则。下方时长、距离、圆角和颜色是 Open-Flame 的产品约定，不是 Apple 官方参数或像素复刻。[Apple：Designing Fluid Interfaces](https://developer.apple.com/videos/play/wwdc2018/803/)

| T16 前基线 | T16 目标 | Why：用户收益 |
| --- | --- | --- |
| 两页各自内嵌 CSS，基础样式重复 | 同一组语义 token、按钮、表单、状态与浮层规则 | 后续功能延续同一风格 |
| 下载入口前展示多个诊断面板 | 新建任务与当前进度靠前，诊断可按需展开 | 常用操作无需穿过技术信息 |
| 各卡片近似等权，长说明占据首屏 | 页面标题、简短说明、任务内容、辅助信息四级层次 | 更快找到下一步 |
| 多个刷新和主操作采用同样蓝色 | 每个任务区域一个明显主操作；刷新、返回使用次级样式 | 操作优先级清楚 |
| 下载/上传的焦点与动效覆盖不一致 | 统一键盘焦点、按压反馈、减少动态效果与高对比模式 | 鼠标、键盘与不同设置下均可用 |
| 列表轮询可能替换整块 DOM | 按稳定任务 ID 更新，保留输入、选择、焦点与展开状态 | 阅读与编辑不中断 |

## 2. 设计 token

颜色通过用途命名，例如 `--of-text-secondary`，不在新控件中重新发明近似灰色。浅色是默认视觉基准；生产实现同时提供“跟随系统 / 浅色 / 深色”。主题选择只保存界面偏好，存储不可用时正常回退。

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--of-canvas` | `#f5f5f7` | `#151517` | 页面背景 |
| `--of-surface` | `#ffffff` | `#202023` | 内容面板 |
| `--of-surface-secondary` | `#ededf0` | `#2b2b30` | 次级操作与分组背景 |
| `--of-text` | `#1d1d1f` | `#f5f5f7` | 主文字 |
| `--of-text-secondary` | `#616167` | `#b5b5bd` | 说明、时间、辅助信息 |
| `--of-border` | `#d8d8de` | `#45454d` | 非交互分隔线 |
| `--of-control-border` | `#85858e` | `#85858e` | 需要可识别边界的输入控件 |
| `--of-accent` | `#0066cc` | `#8abeff` | 链接、焦点、主按钮背景 |
| `--of-on-accent` | `#ffffff` | `#11243b` | 主按钮文字 |
| `--of-success` / `--of-success-bg` | `#18794e` / `#eaf7ef` | `#88dbb1` / `#17362a` | 已明确完成的本地步骤 |
| `--of-warning` / `--of-warning-bg` | `#8a5000` / `#fff4df` | `#ffd18a` / `#3b2d16` | 需要处理或核对 |
| `--of-danger` / `--of-danger-bg` | `#b42318` / `#fff0ee` | `#ffb4ab` / `#421f20` | 失败、危险操作 |

次级文字也应达到正文对比度目标；不可通过降低整个卡片的 opacity 表达“不可用”。禁用控件保留可读原因，成功、警告和错误同时使用文字/图标，不能只看颜色判断。

| 类别 | 基准 |
| --- | --- |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64，代码转换为 rem；非网格值需要具体原因 |
| 内容面板 | 圆角 20px，内距 24～32px；窄屏内距 16～20px |
| 控件 | 圆角 12px，常用控件最小高度 44px，图标按钮同样有 44px 点击区域 |
| 标签 | 圆角 999px，短文本、左右内距 10px；不将整段说明塞入标签 |
| 浮层 | 圆角 24px；阴影浅色参考 `0 12px 40px rgb(0 0 0 / .08)`，普通面板仅轻边框 |
| 聚焦 | `3px solid var(--of-accent)`，外偏移 3px；不得隐藏键盘焦点 |
| 材质 | 仅粘性导航/浮层可用静态 blur 16px 与高不透明度底色；内容、二维码、正文保持实底 |

## 3. 排版与字体

```css
--of-font-sans: -apple-system, BlinkMacSystemFont,
  "Segoe UI Variable", "Segoe UI", "PingFang SC", "Microsoft YaHei UI",
  "Noto Sans CJK SC", sans-serif;
--of-font-mono: ui-monospace, "SFMono-Regular", Consolas,
  "Liberation Mono", monospace;
```

使用设备已有字体，不要求用户安装字体，不依赖外网字体 CDN。Windows 优先保证 Segoe UI 与中文回退的实际效果；Apple 设备自然使用系统字体。数值、时间、大小与进度使用 `font-variant-numeric: tabular-nums`；等宽字体仅用于 ID、hash、路径和诊断内容。

| 层级 | 桌面字号 | 窄屏字号 | 字重 / 行高 | 字距 |
| --- | --- | --- | --- | --- |
| 页面标题 | 40px，可在 36～44px 内自适应 | 30～32px | 600 / 1.2 | 中文 0；英文标题可用 -0.025em |
| 区域标题 | 22px | 20px | 600 / 1.35 | 中文 0 |
| 任务标题/强调 | 17px | 17px | 600 / 1.45 | 0 |
| 正文与输入 | 16px | 16px | 400 / 1.65 | 0 |
| 按钮与标签 | 15～16px | 16px | 600 / 1.4 | 0 |
| 辅助信息 | 14px | 14px | 400 / 1.5 | 0 |
| 技术详情 | 13px | 13px | 400 / 1.55 | 0；允许文本缩放 |

用 `rem` 与 `clamp()` 实现层级，允许浏览器字号和 200% 缩放。中文不统一加负字距，不使用过细字重制造“高级感”。长标题可以换行；账号、标题、执行模式等确认信息不得只有省略号或 hover 才可见。ID/hash 可以折叠，但支持完整展开与复制。

## 4. 布局与完整页面范围

共用顶部产品导航，明确“下载 / 编辑 / 上传”当前位置，导航使用真实链接和 `aria-current`。全站一个主标题，标题下一句说明用途。状态摘要放在可见位置，只有阻塞当前操作的问题使用持续横幅；构建身份和深层诊断放在“运行详情”，保留直接访问路径。

桌面内容最大宽度 1200px，外边距 32px；≥1024px 可以使用主区与 288～320px 辅助区，主区保持至少约 600px。768～1023px 按内容改为单列或上下辅助面板；≤767px 外边距 16px，表单与任务行自然换行。320px 下不出现整页横向滚动。依赖 `min-width: 0`、可折行 flex/grid 和文字缩放，不用强行隐藏溢出掩盖布局问题。

### 下载首页

首屏顺序为“下载”标题与状态摘要 → 新建批次 → 当前任务/成品 → 最近批次。状态、能力、工具链、Cookie 状态和日志放入可展开的运行详情；低磁盘暂停、平台熔断等阻塞仍在相关任务附近显示。

- 新建区保留批次名、分享文本、TXT/CSV 导入、Cookie 模式、提交与字段校验；主要动作仍是创建批次。
- 当前任务按名称、平台、阶段、状态、进度、操作组织；阶段估算与真实传输进度区分。进度未知时使用文字和无确定值进度控件，不制作假百分比。
- 成品区域保留原件、缩略图/字幕等辅助产物、hash/类型、duplicate 的原 owner 关系及“用于上传”入口。
- 批次重开、取消、重试、低磁盘恢复、平台状态和能力证据仍可操作；重试使用当前 Cookie 模式的语义保持不变。
- 日志与 JSON 属于诊断详情；普通成功路径用可读摘要。完整结果与错误排障信息不能被样式升级删除。

### 编辑工作台

按“建立项目 → 编辑草稿 → 核对计划 → 查看成品”组织。下载入口只负责选择来源；打开 `/edits` 不自动复制或处理文件。原件、编辑副本、成品和上传副本的边界要用短句持续显示。

- 项目卡显示来源文件名、大小和当前选择；预览只读取编辑域的来源副本。
- 分段用秒输入并允许从播放器读取当前位置；多个区间按顺序显示，移除与添加不会触发渲染。
- 封面控件在启用后显示抽帧时间、成品比例和可选标题；成品卡直接预览实际 PNG。
- 保存草稿与生成待核对计划是不同状态；生成计划也不开始处理。只有计划卡上的明确确认才排队本地 FFmpeg 处理。
- AI 能力卡必须显示 ready、blocked 或待验收，以及 provider/model；未安装运行时时禁用输入，不能把计划项做成可点击的假功能。
- 成品卡显示类型、大小、时长和 hash 摘要。视频的“用于上传”只导航到显式导入提示，不能直接创建上传草稿或调用平台。

### 上传工作台

按“账号 → 视频 → 内容 → 核对任务”组织，一屏一个明确主动作。已准备好的账号可显示紧凑摘要，添加账号与扫码面板在当前上下文展开；避免每次滚动经过整段引擎说明。三平台身份始终可见。

- 账号：平台与可选备注、添加并扫码、登录状态、检查登录态、取消/重试/完成；T14 后续的断开入口使用同一组件。
- 登录：准备中、二维码已显示、等待用户确认、平台额外验证、成功、过期/失败、取消分别有文本状态；只展示实际后端能提供的状态，不从倒计时猜测结果。
- 二维码：白底、完整边界与足够留白，保持约 224px 图像的稳定区域；不裁切、不圆角化二维码本体、不在码上覆盖图标、不缩放/模糊/翻转码图。只有切换操作或真实失效时更新图像。
- 视频：本地导入、下载成品导入、已导入来源与清空；名称、大小、来源、校验状态清晰。不能通过美化选择器重新引入“用户清空后自动换源”。
- 内容：多账号勾选、标题、简介、标签、Bilibili 分区/原创转载及来源、视频号平台草稿/发布。平台字段按当前选择显示，隐藏时的数据处理沿用经过验证的契约。
- 核对：每个草稿呈现平台/账号、来源、标题、关键平台选项与执行模式。逐项确认继续是明确动作，不能合并为自动批量发送，也不能用登录成功触发上传。
- 任务：等待确认、排队、执行中、取消中、已取消、已接收、平台草稿保存、失败、结果不确定分别显示；“已接收”不等于审核通过或公开。unknown 提供核对提示，不显示一键自动重传。
- 所有列表覆盖空、加载、部分失败、服务异常、长内容和大量历史；T05 的活动项可访问性及 T01 的调度故障必须进入最终视觉验收。

### 新增功能

T07 备份/恢复、T14 账号断开/媒体清理如提供 UI，沿用页面壳、表单、持续错误提示和确认摘要。仅提供 CLI 的能力不为视觉完整性伪造页面按钮。未来增加平台时复用平台身份、账号、模式和状态组件，再增加必要的业务字段。

## 5. 组件与交互契约

按钮统一为主操作、次操作、文本操作和危险操作四类。loading、disabled、pressed、focus、error 都有定义：loading 表示正在处理；disabled 表示当前条件不满足，并有旁边的原因；正常“取消/返回”不能使用危险红色。复制、展开、切换标签不增加确认弹窗。

输入有永久 label、说明及关联错误；placeholder 只给示例。错误使用 `aria-invalid` / `aria-describedby`，保留用户输入，将焦点引导到第一处需要修正的位置。平台字段同样接受键盘和中文输入法；IME 组合期间不触发提交。

默认保留原生链接、button、select、checkbox、details/progress 等语义。用 `<dialog>` 替换既有确认框时必须同步迁移焦点、Escape、取消和已有测试；关闭回到触发者，背景不可误操作，长摘要在窄屏内可滚动。弹窗动画结束不能成为发送请求的条件。

短暂、非阻塞反馈可以使用 toast；需要处理的错误留在相关区域直到解决。不要用自动消失通知承载结果不确定、账号失效或调度故障。倒计时/日志/轮询变化不在整个列表上反复触发读屏播报，仅在有意义的状态变化处播报。

## 6. 动效规范

动效只解释用户刚触发的变化或一次真实状态转换。普通键盘导航、输入、快速切换及轮询刷新即时响应。隐藏元素不得为了等待入场动画而暂时不可点击；快速反向操作应从当前视觉状态继续。

| 场景 | 默认处理 | 边界 |
| --- | --- | --- |
| 指针按压按钮 | 缩放到 0.98，松开约 120ms 恢复 | 键盘激活和 reduced motion 不缩放；操作仍由正常 click/submit 提交 |
| hover | 120ms 背景/边框变化 | 仅 `(hover: hover) and (pointer: fine)`；不让整个任务行漂浮 |
| 用户展开小面板 | opacity + 最多 6px 位移，180ms | 可中断；原生 details 可直接展开，避免每帧动画 height |
| 登录容器首次展开/确认浮层 | 进入 240ms，退出 160ms | 二维码出现后立即稳定；不动画二维码本体 |
| toast | 最多 6px 位移 + opacity，180ms | 入退同一路径；焦点不被通知抢走 |
| 状态标签 | 必要时 120ms 颜色/透明度变化 | 同一状态的轮询结果不重新播放 |
| 进度 | 更新真实数值；必要时 ≤120ms 视觉平滑 | 不越过后端值，不在未知进度上编造递增 |

统一缓动 `cubic-bezier(.23, 1, .32, 1)`。默认使用 CSS transition，明确列出属性，不使用 `transition: all`；有程序化打断需求时使用 WAAPI。当前两页不增加拖拽/惯性功能，仅为动效引入大型运行依赖也不作为默认方案。未来确有直接操控手势，再评估可携带速度的 spring 实现。

`prefers-reduced-motion: reduce` 去掉位移、缩放、弹性与自动平滑滚动，允许即时状态变化。`prefers-reduced-transparency: reduce` 和 `prefers-contrast: more` 使用实底与清晰边框；`forced-colors` 保留系统色、焦点及状态文字。基础布局在不支持这些增强查询或 backdrop-filter 时同样完整。

## 7. 实现与后续开发规则

生产页面仍由[下载 HTML](../src/video_download_control/web.py)与[上传 HTML](../src/video_download_control/uploads/web.py)中的字符串提供，页面自身保留布局和业务 JavaScript。T16 已建立下列共享资源边界：

- [共享样式 `open-flame.css`](../src/video_download_control/static/open-flame.css)是 token、主题、页面壳、表单、按钮、状态、响应式与辅助功能降级的生产来源，对应应用内 `GET /assets/open-flame.css`。
- [主题脚本 `open-flame-shell.js`](../src/video_download_control/static/open-flame-shell.js)只管理“跟随系统 / 浅色 / 深色”偏好及存储不可用时的回退，对应应用内 `GET /assets/open-flame-shell.js`；业务提交、登录和轮询不由它触发。
- [静态资源加载器](../src/video_download_control/ui_assets.py)使用固定 allowlist 从 Python 包读取这两个文件，应用响应使用明确 Content-Type、`no-cache` 与 `nosniff`。不接受用户提供的资源路径。
- [设计预览](design-preview.html)通过相对路径 `../src/video_download_control/static/open-flame.css` 直接读取同一 CSS，因此从仓库本地打开时不依赖应用服务器或外部网络；预览特有的片段布局和演示交互仍保留在预览文件内。

以上结构已用于两张生产页面。源码行为回归与真实浏览器矩阵见 [0.25.0 T16 证据](../validation/iteration-0.25.0-t16-frontend-evidence.md)；源码 ZIP/sdist/wheel 的内容一致性和独立安装仍以同批包外 release receipt 为准，不能从源码文件存在推断。

0.26.0 新增的逐平台文案、封面和定时控件继续使用同一结构；当前真实浏览器的桌面/窄屏与交互结果见 [0.26.0 上传参数证据](../validation/iteration-0.26.0-upload-parameters-evidence.md)。该记录只证明禁止远端调用的本地页面范围。

- 共享 token 和通用组件只有 `open-flame.css` 一个生产来源；预览不得重新定义 `--of-*`，只保留合成样例所需的局部布局。
- 新建或修改控件时先查本规范，复用现有语义 token；需要新 token 时说明使用场景并同步预览。避免全局 `button` 或 `.row` 改动意外改变另一个页面。
- UI 调整与上传业务调用边界分离，保留已有 ID/事件契约或同步更新真实行为回归；不通过删除断言让美化通过。
- 上传多 mode 草稿的部分成功重试沿用同一提交幂等键；二维码 nonce 只在既有请求头传递，不能因组件重构进入 URL/日志。QR 过期、取消、换 revision 或 pagehide 时立即清除 Object URL；同时停止所属 timer/WAAPI/RAF，BFCache 返回只恢复一次。
- 轮询按 ID 更新稳定 DOM；保留选区、IME、焦点、滚动、勾选、details 和空来源，避免整个表单反复 innerHTML 重建。
- 状态组件消费真实 API 数据；T04 未完成时保留诚实的未知状态，不能用绿色设计稿替代运行证据。
- 静态资源必须随源码 ZIP/sdist/wheel 一起打包，在正确 Content-Type/CSP/cache 与包内容身份规则下提供；不依赖外部字体、样式、图标或脚本 CDN。源码中存在资源或路由本身不等于发行包已经验证。
- 设计基准变更先更新本文件与预览，再迁移受影响组件；评审说明变更原因、涉及页面、交互状态和验证结果。用户后续新的明确设计要求优先。
